Get started

Connect your agent to the store, then ask it to set implementator up. The first run takes a few minutes and a handful of answers.

What you need

  • An agent that can sign in to Agensi: Claude Code or Codex CLI are the two we have tested.
  • Git. Your notes live in a git repo.
  • Python 3.8 or newer. Every script in the pack is Python. You do not need bash.
  • Your code in a git repo.
  • Optional: gh or glab for pull requests and CI, and a Playwright MCP server for browser self-tests.

1. Connect your agent

Claude Code

claude mcp add --transport http agensi https://mcp.agensi.io/mcp/auth

Then open /mcp, choose Authenticate, sign in with the account you bought the pack with, and click Allow.

Codex CLI

codex mcp add agensi --url https://mcp.agensi.io/mcp/auth
codex mcp login agensi

Sign in and click Allow. On Windows, read Codex on Windows as well.

Only the newest app stays connected. Each app you sign in from counts as one agent, and signing in from a new one disconnects the others. Switch agents by connecting the new one, or in Dashboard → MCP on Agensi.

Other agents are on Agensi's setup page. They can connect, but this pack has not been tested on them.

2. Run the setup

Open a session in the folder that holds your code, and say:

I just bought implementator. Set it up for me. My code is in the tally folder here.

Your agent then:

  1. Asks where the notes repo goes, and recommends a folder beside your code. Never put it inside a code repo. Keep the path short: see the Windows path limit.
  2. Offers a small pointer file for the notes repo, so new sessions there know to start with implementator. It is written only if you say yes.
  3. Asks six questions, each with a recommendation based on what it found on your machine. Answer the ones you care about; ok accepts the rest.
  4. Shows the change as a diff and writes implementator.json only after your yes.

The six questions

QuestionYour choices
How should finished work leave?Draft pull request; solo (push, no PR); team (draft PR, worktrees, CI watched); or you-commit (the agent stages and drafts the message, you do the rest).
Which issue tracker do your ticket ids come from?None, Linear, Jira, GitHub, GitLab, Azure Boards, other.
Where is the code hosted?Auto reads it from each repo's remote, or name one.
How should the browser self-test run?Which driver, visible or headless, and whether to record.
Watch CI after each push and fix what goes red?Yes or no.
Model cost?Balanced, economical or maximum quality.

None of this is final. Every answer can be changed later: see Configuration.

What the notes repo looks like

implementator-notes/
  implementator.json          your defaults
  epics/                      work that spans several projects
  projects/
    tally/cli/                one connected project
      project.json            its settings
      skills/                 coding, testing, review, repo
      ADD-JSON-OUTPUT/        one feature
        workstreams/json-output/
          RESUME.md           the journal, newest first
          plans/ docs/ tests/
  archived/                   finished work, path kept

It is an ordinary git repo. The agent reports what is uncommitted and leaves the commit to you, unless you tell it to commit the notes.

Codex on Windows

Three things are different here, and all three come from Codex's Windows sandbox.

  • Allow commands to run. In our tests workspace-write rejected every command until the sandbox was set to its unelevated mode, which keeps the sandbox on: 
    codex -s workspace-write -c 'windows.sandbox="unelevated"'
    We tested this with codex exec. Do not turn the sandbox off to get around it.
  • Node cannot start child processes, so npm test fails with spawn EPERM on any project that uses node --test or spawns its CLI in tests. Python and git are fine. The agent will ask you to run the suite outside the sandbox and paste the result. That counts as the run.
  • gh cannot read your sign-in, so it may say the token is invalid when it is not. The pack reports this as a warning, not a failure.
