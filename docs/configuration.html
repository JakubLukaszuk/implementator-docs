Configuration

Settings decide how each stage runs: who commits, which browser, how much model. They never decide whether a stage runs.

Modes, never gates. No setting can skip the plan approval, the review, the manual test or your confirmation before a commit. Ask to turn one off and the agent will say no.

How to change a setting

Say it in plain words. The agent names the key and the file, shows the diff, and writes only after your yes.

Use implementator. Turn on CI watching for tally/cli.
What does tally/cli use for pull requests?
Use the team preset for all projects.

Where a value comes from

  1. The project: projects/<product>/<id>/project.json.
  2. Your defaults: implementator.json at the notes root.
  3. Built in: the defaults on this page.

The first one that sets a key wins. A project overrides your defaults one key at a time, so it never has to repeat a whole block.

{
  "version": 1,
  "defaults": {
    "features": {
      "git": { "pr": "ready" },
      "selfTest": { "maxIterations": 3 }
    }
  }
}

Presets

A preset is a named set of settings. It goes through the same diff and the same yes as any other change.

PresetWhat it sets up
backend-apiA service with no screens: the self-test calls the live API over HTTP and no screenshots are taken. Apply it to that component, not to defaults.
headless-ciNo browser windows while it works: Playwright runs headless, CI is watched after the push, and one visible drive at the end shows you the result.
routing-economicalLower model cost: mechanical stages and coding on the cheap tier, the reasoning gates (plan, triage, review) at their floor of standard. A stage that stalls is re-run once on strong before its result is trusted.
routing-max-qualityHighest quality, highest cost: coding, the self-test and the reasoning gates all on the strong tier at high effort.
soloOne person, no review queue: the agent commits and pushes after your confirmation, and opens no pull request.
teamA shared repo: each workstream in its own worktree, a draft pull request, and CI watched until it is green.
thorough-evidenceMore proof per change: a smoke pass over the core flows, screenshots on every UI change at three sizes and in dark mode, and a recording of any drive that fails. Recording needs the Playwright MCP server started with --caps=devtools.
you-commitYou keep the keyboard on git: the agent stages the change and prints the commit message; you commit, push and open the PR.

Models

Each stage runs on a model tier, not a named model: cheap, standard or strong. Your agent maps a tier to a real model. Effort is low, medium, high or auto.

The plan, the failure triage and the review can never go below standard. These are the built-in values:

StageWhat runsTierEffortOwn subagent
orientReading the state of the workcheaplowno
planWriting the planstronghighno
codeWriting the codestandardmediumno
staticChecksLint, typecheck, testscheaplowno
selfTestDriving the appstandardmediumyes
triageWorking out why something failedstronghighno
reviewThe code reviewstronghighyes
manualScenarioWriting your manual teststandardlowno
commitCommit and pull requestcheaplowno
postPushWatching CIcheaplowno

Each stage takes the settings orchestration.stages.<stage>.model, .effort and .isolate. isolate runs the stage in its own subagent, where your agent has them. If it does not, the agent runs that stage itself and says so.
