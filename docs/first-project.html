Your first project

From a code repo to one finished change. The examples come from a real run on tally, a small word-count CLI.

The skills are not commands you type. You say what you want in your own words, and the agent loads the skill. To be sure it uses the pack, start with "Use implementator".

1. Connect the repo

Connect the tally repo to implementator.

The agent reads the repo and comes back with what it found: type, test and launch commands, and how it would verify a change. It asks three things: the project's name, its verification profile, and any hard rules, such as "keep it dependency-free". Nothing it could not confirm is invented: if a repo has no lint command, none is written down.

A project is addressed as product/id, such as tally/cli.

2. Approve its skills

Next the agent proposes a table of skills for this repo, with the evidence for each, and lists any it would skip. A CLI with no database gets no database skill. Each generated skill says which assumptions you should confirm and which gaps it noticed, such as a file with no tests. It reports those gaps and does not fix them on its own.

The skills go in your notes repo, not your code repo.

3. Preflight

The agent checks that the project is ready: config valid, toolchain present, dependencies installed, commands real. The verdict is READY or a list of what to fix.

4. Start the work

Start the real work: tally should take a --json flag that prints total and unique as JSON

The agent opens a workstream, claims it for this session and writes a plan. No code gets written until you approve that plan. Read the summary at the top. If you ask for a change, you get a revised plan to approve.

Unsure what you want yet? Say "grill me on this first", and it will ask until the decisions are settled.

5. Let the loop run

After approval the agent writes the code and tests, runs your checks, drives the app or CLI itself, including the failure paths, and reviews the change. If anything fails it goes back and fixes it. You will see the result, not every step.

6. Run the manual test

The agent gives you a short table of commands and expected results. Run them yourself and report back:

Manual test passed, every row matched the table.

If a row does not match, say what you saw. Any code change sends the work back through tests and review.

7. Commit

With the default settings, the agent commits and pushes after you confirm, and opens a draft pull request. With you-commit it stages the change on a branch and gives you the message.

8. Close it out

Committed. Close it out.

The agent marks the work resolved, journals it, and moves it to archived/ with its path kept. Nothing is deleted. Then it reports what is uncommitted in the notes repo and leaves that commit to you. To let it make that commit, say "commit the notes".
