Troubleshooting

Most of these come from real test runs. The messages are quoted as the pack prints them.

The agent skipped a test, the review or the manual pass

Ask it: "What is left before this is done?" In our runs that was enough for the agent to name what it had skipped. Then say "Go on, finish the loop."

The rules are instructions and an agent can drift from them, more so on a long session. Starting a new session reloads them. Closing is checked by a script as well: see below.

not resolved, nothing changed. Missing: ...

The script that closes a workstream found no plan, code review, self-test record or manual run in its folders. Finish what it names. If the work changed no code, tell the agent so and it can close it with --no-code. If the work is abandoned, close it as canceled.

spawn EPERM when running tests

This is Codex's Windows sandbox refusing to let Node start a child process. Your code and tests are fine. Run the suite in a normal terminal and paste the result to the agent. Do not let it rewrite the tests to suit the sandbox. The pack tells it not to, but this is the one to watch for.

Codex says every command is blocked by policy

On Windows, set the sandbox to unelevated mode as shown in Get started.

CreateFileMapping or bash errors in Codex on Windows

Git Bash cannot start inside that sandbox. The pack does not need it, because every script is Python. If your project's commands are written for bash, the check script falls back to the system shell, so a command that truly needs bash has to be run by you.

gh says the token is invalid, but you are signed in

A sandboxed agent often cannot read the system keyring. Run gh auth status in a normal terminal to be sure. The pack shows this as a warning for that reason.

cannot create ... (263 characters): No such file or directory

Windows stops at 260 characters unless long paths are turned on, and a workstream's files sit several folders deep. Move the notes repo somewhere short, like C:\notes, or use shorter initiative names. Git may need core.longpaths for the same reason, and that is your choice to make: the agent should not change it.

set IMPL_NOTES_ROOT to the notes repo root

The agent ran a script without saying where your notes are. It will usually correct this by itself. On PowerShell the variable lasts for one command, so it has to be set on the same line.

BLOCKED: live claim by ...

Another session holds this workstream. Finish there, or wait for the claim to expire after four hours. If that session is gone, tell the agent to take over; it will use --force on your word.

Settings fail to apply on PowerShell, or accented text comes out damaged

PowerShell strips quotes from JSON arguments and re-encodes piped text. The pack tells the agent to pass both through a temporary file. If you see damage in a journal, remind it to use --body-file.

The agent suddenly cannot reach the pack

Another app probably signed in to your Agensi account, and only the newest stays connected. Sign in again from the agent you want to use. See Connect your agent.

The review says it was not independent

The review is meant to run in separate subagents. If your agent could not start any in that session, it does the review itself and says so. Ask for a re-run with independent subagents if the change matters. It costs more.

A temporary script was left behind

Each script runs from a temporary file that the agent deletes afterwards. If a delete is refused, the agent should give you the exact path, and you can remove the file yourself. It holds no private data.

Still stuck

Message the creator through Agensi, and include the message you saw.
